# 叙事模块（`narrative/`，v0.6.0 并入扩展）

> 这一层不写剧情。它只做一件事：**把聊天里已经发生的事实记成账，再把账本交回给模型。**
> 世界书判定（`core/`、`runtime/`）不经过这里，`narrative/` 也不修改任何条目。
>
> **v0.7.1 起定位回调（D-0043）**：它是**确定性状态账本**，不是事件驱动器、不是玩法引擎、不是游戏。
> 不做 `emit`/事件队列/级联/可视化编程；"复杂"来自它和条目、规则、宏、界面的组合（参考文档 §10.12）。
> 代码里 `events` 字段保留原名，但语义只是"自定义状态操作"，不发出事件。

## 为什么不是"让模型维护状态"

让模型自己记背包，必然出现三件事：数字算错、忘了扣、前后矛盾。所以分工是：

- **模型只写事实**：`[[ILB:获得:铜钥匙]]`、`[[ILB:关系:艾琳/+1]]`、`[[ILB:地点:王城/地窖]]`。
  不写类型、不写数值、不写规则、不做平衡。
- **ILB 记账**：数值、容量、上限、互斥、冷却全部由声明决定。
- **状态是重放出来的**：`状态(第 N 条) = fold(消息 1..N)`。滑动、重生成、删消息、编辑消息、
  刷新页面都只是重算一遍，不需要版本号，也不会出现"账本和对话对不上"。

## 四层模型（加玩法不改核心）

| 层 | 文件 | 作用 | 例子 |
|---|---|---|---|
| 实体目录 | `catalog.js` | 有什么 | 铜钥匙（物品，重 1）、圣剑（装备，重 5）、王城（地点） |
| 状态变量 | `schema.js` | 记什么 | `背包：列表（上限 8 件，总重 ≤ 20）`、`委托：枚举` |
| 约束 | `schema.js` | 什么算合法 | `max` / `sumMax` / `range` / `mutex` / `require` |
| 规则 | `engine.js` | 事实如何改状态 | `获得 物品 → 放进背包`、`圣剑入手 → 标记 圣剑` |

三条纪律（D-0040）：

1. **能算的都不许存**：剩余格、总重量、是否满、条目数一律由 `derive()` 现算。
2. **原子拒绝且可见**：一条事实要么整条生效，要么完全不变；拒绝带原因；看不懂的标记进 `unknowns`。
3. **有界**：规则只做"匹配 + 有限效果"，不做循环与递归；聚合用内置 `count/sum/any/all`。

还有一条实现细节（D-0039 第 5 条）：**规则的触发条件只看这条事实发生之前的状态**。
否则同一条事实里前面规则改出的值会把后面的规则带起来，规则表的书写顺序就会改变语义。

## 事实语法

| 动词 | 写法 | 含义 |
|---|---|---|
| 获得 | `[[ILB:获得:铜钥匙]]`、`[[ILB:获得:药水×2]]` | 放进列表、可能改标记 |
| 失去 | `[[ILB:失去:铜钥匙]]` | 从列表移除 |
| 使用 | `[[ILB:使用:药水]]` | 触发"用掉"类规则（冷却、回血…） |
| 关系 | `[[ILB:关系:艾琳/+1]]`、`[[ILB:关系:卫兵/-2]]` | 关系表累加，方向可正可负 |
| 地点 | `[[ILB:地点:王城/地窖]]` | 从 → 到 |
| 标记 | `[[ILB:标记:圣剑]]` | 置位一个开关 |
| 解除 | `[[ILB:解除:圣剑]]` | 清除开关 |
| 见过 | `[[ILB:见过:地窖]]` | 记"见过但不持有" |

`tick` 不是模型写的：每条消息末尾由引擎自动发一次，用来递减"冷却 N 轮"。

### 自定义事件与别名（v0.7.0）

不是所有角色卡都是 RPG。声明里可以登记自己的事件名，规则照常按 `on:'event'` 响应：

```json
{
  "events": ["突破", { "id": "结契", "label": "与角色结契" }],
  "verbs": { "拾取": "获得", "捡起": "获得" },
  "rules": [
    { "id": "突破筑基", "on": "event",
      "when": { "event": "突破", "name": "筑基" },
      "effects": [{ "op": "inc", "var": "灵力", "amount": 10 }] }
  ]
}
```

正文写 `[[ILB:突破:筑基]]`、`[[ILB:拾取:灵石]]`。`拾取` 解析后仍是"获得"；`突破` 是自定义事件，
由 `on:'event'` 的规则认领。没登记就写会被当成"看不懂"；登记了但没有规则认领，会被标成"未认领"
——两种失败都会写在消息块里，不会静默改状态。

## 设置项（`extension_settings.independent_lorebook.settings`）

| 键 | 默认 | 说明 |
|---|---|---|
| `narrativeEnabled` | `false` | 总开关。关着时不注入、不画块，行为与 v0.5.0 一致 |
| `narrativeInject` | `true` | 只关注入、保留消息块（调试用） |
| `narrativeBudget` | `600` | 注入文本的字符预算，夹在 120–2000 |
| `narrativeDeclaration` | `null` | `null` = 用 `preset.js`；替换后存设置，升级不覆盖 |
| `narrativeCheckpointEvery` | `5` | 最新几条现场重算；更早的折成检查点。`0` = 不存检查点，夹在 0–50 |

「叙事」标签页：开关、预算、检查点间隔、账本预览、查看账本、重放一次、重建账本、编辑声明、
复制编写说明、恢复示例声明。设置页只保留世界书自己的选项。

## 注入

- key：`ILB_NARRATIVE`（与世界书的 `ILB::<pos>::<depth>::<role>` 分开，避免互相清空）。
- 位置：IN_CHAT、**深度 0（贴在最新一条消息之后）**、system。深度 0 是 v0.6.2 修的：
  原来用深度 1，实测会把最新一条用户消息隔在账本之后，那条消息里的事实就落在账本外面。
- 内容：`【账本】按已发生的 N 条对话重放得出；与正文冲突时以账本为准。`
  + 可选"本轮变化（改前 → 改后，最多 4 行）" + 当前状态（带"背包 4/8，重 19"这种约束现状）
  + 用法说明（最多 3 条、示例）。
- "本轮变化"是 v0.7.0 加的：模型不需要自己算加减，直接看到"生命 90 → 89"这种差值来润色。
- 关掉开关时写空串清除，不残留旧账本。

## 事件

| 事件 | 动作 |
|---|---|
| `MESSAGE_RENDERED` / `CHARACTER_MESSAGE_RENDERED` | 只补这一条消息的块 |
| `USER_MESSAGE_RENDERED` / `MESSAGE_SENT` | **立刻重算注入**（最新消息可能还没进 `chat`，见上面"深度 0"） |
| `MESSAGE_EDITED` / `MESSAGE_SWIPED` / `MESSAGE_DELETED` / `MESSAGE_UPDATED` / `CHAT_CHANGED` | 整段重算（280ms 防抖） |
| `GENERATION_STARTED` | 刷新注入（兜底） |
| `GENERATION_ENDED` | 重算块 |

拿不到事件源时只报一次 warn，不阻止手动"重放一次"。

## 性能

重放是 O(消息数)，但**不是每次都从头算**：`replay()` 给每条消息存一个指纹（djb2），
同一条聊天 + 同一份声明 + 前缀没变时直接复用前缀状态；只有编辑/滑动/删除会影响的那一段重算，
删楼层时缓存尾巴跟着剪掉。缓存只影响速度，不影响结果——同一输入必须得到与全量重放相同的状态
（`tests/narrative-plan.test.mjs` 里有对应用例）。

按一次典型 200 条楼层、每条 200 字算：全量重放约 4 万字字符串扫描 + 规则匹配；增量重放通常只走
最新 1～3 条。真正的开销大头其实是**画块**（DOM），所以 `renderOne` 只补一条，不整页重画。

## 检查点（v0.7.0）

问题：如果用户装了楼层管理/记忆增强类插件，把旧楼层隐藏或删掉，纯重放会跟着丢掉那些事实。

做法：**最新几条现场重算，更早的折成一份状态存下来**。

- 间隔由 `narrativeCheckpointEvery` 决定（默认 5，0 = 关闭）；
- 检查点按"聊天 key + 声明指纹"存 `{upto, state, totals}`，写在
  `extension_settings.independent_lorebook.settings.narrativeCheckpoints`，只保留最近 8 条聊天；
- 刷新时从 `upto` 续算；旧楼层被隐藏/删除/改写**不会**让检查点失效（这正是要保住的语义），
  代价是"账本与可见正文可能不一致"；
- 想回到"完全按当前正文算"，点「叙事」页的「重建账本」清掉检查点；
- 检查点覆盖的旧消息不再单独画块（避免块里的状态和检查点对不上）。

## 常见问题

**写了 `[[ILB:生命:89]]` 但账本没变？**
`生命` 不是八个内置动词，也不在 `events`/`verbs` 里，这条会被标成"看不懂"（消息块里 `? 看不懂：[[ILB:生命:89]]`）。
设计上 AI 不直接改数值——数值变化要由规则决定。三种做法：
① 写"事件"事实，例如 `[[ILB:使用:受伤]]`，用规则 `on:'use', when:{name:'受伤'} → inc/dec 生命`；
② 在声明里登记自定义事件 `[[ILB:受伤:左臂]]`，用 `on:'event', when:{event:'受伤'}` 响应；
③ 想直写数值，需要"直接设值"事实类型（目前**没有**，见 §10.7 待定）。

**写了 `[[ILB:获得:测试道具]]` 但显示"未认领"？**
目录里没有"测试道具"，也没有规则匹配它。到「叙事 → 编辑声明」把它加进 `catalog.entities`（带标签/重量），
或者加一条 `on:'gain'` 的规则；否则引擎不知道拿它做什么，只能如实说"没有规则处理"。

**怎么把 `[[ILB:…]]` 从正文里藏起来？**
按用户要求，扩展**不修改**消息正文（改了会和宿主的重画打架）。用 SillyTavern 的正则扩展：
匹配 `\[\[ILB:[^\]]*\]\]`、替换为空、只在"显示"阶段生效；存档原文保留标记，重放才不受影响。

**楼层被别的插件隐藏/删除，账本会怎样？**
现状：账本跟着当前 `chat` 数组重算——隐藏/删除的楼层不再贡献事实，编辑过的楼层按新正文重算。
这是"账本永远等于对话"的代价。要"删楼层也不丢事实"就得加一份事件日志（见 §10.7 待定①），
那会引入"账本与正文不一致"的第二真相，需要先定规则再动。

## 消息块


## 已知边界

- **真实 SillyTavern 对话端到端还没跑过**：探针只证明 DOM 与注入接线，不证明模型下一轮会遵守账本。
- 检查点只存"状态 + 累计统计"，不存每个旧楼层的事实原文；「重建账本」后，已被隐藏的旧楼层无法恢复。
- 正文里的标记不剥离（`10.5.4`）；手机上的账本坞只是"看"，不能改。
- 手动补记（`manual` 事实）引擎支持，但还没有界面入口；可视化事件编辑器未做。
- 表达不了"排序取最优""配方组合爆炸"这类策略——按 D-0040 留给脚本钩子，不走默认路径。
