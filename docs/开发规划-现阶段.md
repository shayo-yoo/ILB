# ILB 现阶段开发规划（人话版）

> 这份写给"想用 ILB 做出东西的人"，不是写给程序员的。
> 目标是把话说清楚：我们要回到哪里、做成什么样、分几步、每步你能看到什么、什么算做完。

---

## 0 · 一句话

**回到世界书本身：让条目里的"逻辑流程图"能读变量、做计算、按结果带出别的条目——用很小的零件，拼出抽卡、判定、连锁剧情这类复杂效果。**

记忆（角色状态、物品账本）**不做进这个扩展**，以后单独做一个以记忆为核心的扩展；这里只留接口。

---

## 1 · 你会得到什么

三件看得见的变化：

1. **条目能读写"变量"**：比如 `幸运`、`抽卡次数`、`保底计数`。玩家在面板上能改，条目正文能用 `{{ILB:chat.幸运}}` 显示。
2. **逻辑流程图多三件事**：
   - 读/写变量（已有比较和计算，补上"存下来"）；
   - 调用一个本地小函数（如"掷骰""四舍五入""查表"）；
   - 带出另一个条目（"这次抽中了，把'SSR 描写'那条放进来"）。
3. **状态面板**：聊天旁边一页，列出变量和"动态条目"，玩家能点按钮 / 改数值，改完立刻影响下一次注入。

复杂效果不是新引擎给的，是这三件事**连起来**给的。

---

## 2 · 用"抽卡"讲一遍（这就是验收标准）

玩家说一句"抽卡"，背后发生的是：

| 步骤 | 谁在做 | 做什么 |
|---|---|---|
| 1 | 条目"抽卡台"的触发词 | 检测到"抽卡"，这条被选中 |
| 2 | 逻辑流程图：判断 | `抽卡次数 > 0`？不是就结束 |
| 3 | 逻辑流程图：调用函数 | `掷骰(幸运)` → 得到 0–100 的数，写进变量 `本次结果` |
| 4 | 逻辑流程图：比较 | `本次结果 >= 60`？是 → 走"成功"分支；否 → 走"失败"分支 |
| 5 | 逻辑流程图：改变量 | `抽卡次数 -1`、`保底 +1`；成功时 `保底 = 0` |
| 6 | 逻辑流程图：带出条目 | 成功 → 带出"SSR 描写"；失败 → 带出"普通结果" |
| 7 | 被带出的条目 | 各自还可能带出下一层（最多 2 层），到顶就停 |
| 8 | 注入 | 把展开后的正文交给模型 |
| 9 | 模型 | 只负责把"这次抽到了什么"写成剧情，不参与算概率 |

每一步都只是一个简单判断或一次赋值；合起来就是一个抽卡系统。**这就是"简单功能涌现复杂功能"。**

---

## 3 · 边界：做与不做

**做：**

- 变量（每条聊天独立，面板可改）；
- 流程图的三种新动作（存变量 / 调函数 / 带出条目）；
- 有限连锁（默认 2 层，可调，最多 5 层；同一轮不重复带出同一条）；
- 诊断页能看见"谁带出了谁、为什么没带出"；
- 宏：在条目的正文里显示变量值；
- 动态条目：条目自带几个字段，面板上能改；
- 给别的扩展留 4 个口子：读变量、写变量、注册函数、监听"条目被激活"。

**不做：**

- 不做游戏引擎、不做战斗系统、不做玩法模板；
- 不让 AI 直接改状态（只能通过本地逻辑和玩家操作）；
- 不做无限递归、不做脚本（不写代码，只连积木）；
- 不把记忆模块装回来；它以后是另一个扩展，用这里的口子接。

---

## 4 · 分五步走

### 第一步：搬家（让扩展变轻）

- 把 v0.6–v0.7 加进去的"记忆"部分（账本、检查点、叙事页）整体移到旁边的 `memory/` 目录，**不删、继续留档**，但不再装进扩展；
- 悬浮球里那页"叙事"先撤掉；设置页恢复成只管世界书；
- **你会看到**：扩展回到"世界书控制器"的样子，启动更快、出错面更小。
- **算完成**：关掉扩展再开，世界书功能与以前一致；测试全绿。

### 第二步：变量（地基）

- 每条聊天一份变量表；面板能看、能改；
- 条目正文可以用 `{{ILB:chat.名字}}` 显示；没定义时显示一个醒目的"未定义"，不装作空；
- **你会看到**：在面板里把 `幸运` 从 50 改成 80，下一条消息里条目正文显示的就是 80。
- **算完成**：改值 → 重发 → 注入里的数字跟着变；换一条聊天，值不串。

### 第三步：流程图的三件新动作

- 在现有流程图里加三种积木：**存变量**、**调函数**、**带出条目**；
- 自带几个小函数：掷骰（可给权重）、取整、取最大/最小、查表；
- 宏和流程图用同一套变量名，不会两套；
- **你会看到**：画一个"如果 幸运>50 就带出好运条目，否则带出倒霉条目"，发一句话就能触发。
- **算完成**：不写代码，只在流程图里连线，就能做出"按变量分支"的效果。

### 第四步：有限连锁（把积木串起来）

- "带出条目"最多 2 层（可在设置里调，上限 5）；同一轮不重复；成环会自动停；
- 诊断页显示一条链：`抽卡台 → 掷骰=37 → 失败 → 带出"普通结果"（第 1 层）`；
- **你会看到**：抽卡那套能完整跑通，且每一步都能在诊断页找到原因。
- **算完成**：抽卡示例跑通；故意写一个环，它会停下并说明"到上限了"。

### 第五步：动态条目 + 状态面板（把 UI 用起来）

- 条目可以声明几个字段（数字、开关、选项、短文本）；
- 面板按字段生成输入框/按钮；玩家改完立即写回；
- 这些字段可以参与流程图判断，也可以被宏显示；
- **你会看到**：不用打开 JSON，玩家就能在面板里"加一次抽卡次数""把幸运调到 80"。
- **算完成**：整个抽卡流程里，玩家只靠面板和一句话就能玩，不需要改任何文件。

### 可选第六步：接口文档 + 记忆扩展试水

- 把四个口子写成半页说明，附一个最小例子；
- 用这个口子写一个**独立**的小记忆扩展（不在本仓库里），验证"别的扩展能读写变量、能注册函数、能监听激活"。
- **算完成**：记忆扩展不改 ILB 一行代码就能工作。

## 5 · 抽卡验收清单（做完就打勾）

- [ ] 说"抽卡"，本地掷骰，结果与诊断页一致；
- [ ] 成功率受 `幸运` 影响；把 `幸运` 调到 100，必中；
- [ ] 失败会走失败分支，成功会清零保底；
- [ ] 抽卡次数用完时，提示"没次数了"，不再掷骰；
- [ ] 连续抽卡不会无限带出；超过 2 层会停；
- [ ] 模型只叙述结果，不自己编数值；
- [ ] 玩家在面板改值，下一次注入立刻生效；
- [ ] 换一条聊天，变量和次数从初始值开始。

## 9 · 进展（2026-10-24，v0.8.1）

五步都已落地，代码在扩展里，账本代码在仓库根目录 `memory/`（留档，不随扩展加载）：

1. **搬家**：`narrative/` → `memory/narrative/`；扩展不再加载/注入账本。
2. **变量**：`core/vars.js` + repository 的 `getVars/mergeVars/deleteVar`；条目正文写 `{{ILB:名字}}`；面板多一页「状态」。
3. **流程图三件事**：节点「记住」（写变量）、「激活条目」（拉条目，绕触发词）、「计算」勾「存进聊天」可跨轮记账。
4. **有限连锁**：`maxActivateDepth` 默认 2、上限 5、0 关闭；广度优先，同一轮同一条目只激活一次。
5. **动态条目 + 状态面板**：条目可声明 `fields`（数字/开关/选项/文本，最多 12 个），「状态」页按类型生成控件；手机顶部坞显示前 3 个变量，点它去「状态」页。

**怎么自己看一眼**（不连模型）：

- 命令行：`cd extension && node tests/gacha-demo.mjs` —— 四轮输出（次数 3→2→1→0、幸运 ≥80 出金卡）。
- 界面：打开面板 → 状态页 → 给任意书里的条目加 `fields`，回来就能看到控件；手机布局顶部会有变量坞。

**留给真机确认**：变量是否真的随聊天保存、换聊天是否隔离、宏是否与 ST 自带宏打架、级联两层的实际观感、状态页控件在手机上好不好按。

## 10 · 进展（2026-10-25，v0.9.0）

这一轮来自《ILB改进想法.md》和你后来的拍板（「保留两套触发」「跳转只限次数」「AI 只改变量」「三期一次做完」）。

**做了什么**

1. **独立逻辑**：规则页最下面多一栏「独立逻辑」。它自己带触发词，**不命中世界书条目也能跑**；能判断楼层数、AI 回复里有没有某个词、改变量、说一句话进提示词、点名带出别的条目/逻辑。条目那边保留原样，多了一个「等候模式」（不自己出现，只等点名）。
2. **流程两个新节点**：「跳转」（填目标节点、最多跳几次、超了终止还是继续；允许往回跳）、「调用逻辑」（把另一条逻辑当子步骤跑，写变量会带回来）。流程里还能复制/粘贴步骤，粘贴出来的是一份新副本。
3. **AI 调用逻辑**：设置页默认关闭。打开后 AI 在正文里写 `[[ILB:扣款(3)]]` 就真的执行，只能调用你在逻辑编辑页「允许 AI 调用」的那些，只能改聊天变量，成功失败都进诊断页。
4. **编辑器体验**：触发词可选择只看用户 / 只看 AI；添加步骤改成先点「＋ 添加一步」再选类型；成立/不成立两条分支不同颜色；「激活条目」和「调用逻辑」的选择框能直接搜；书架支持勾选批量启用/停用/删除；逻辑可以导出/导入 JSON。

**怎么自己看一眼**（不连模型）：

- `cd extension && node tests/logic-demo.mjs` —— 四段：没有条目的书跑逻辑；AI 调用扣款成功；调用没开放的名字被拒；关掉开关后没反应。
- 界面：规则页 → 最下面「独立逻辑」→ 新增逻辑；设置页 → 「AI 调用逻辑」两张卡。

**留给真机确认**（这一批只过了单元测试和假 DOM）：

- 真实模型会不会主动写 `[[ILB:名字(参数)]]`（`aiCallScan` 默认只看最近 3 条 AI 消息，太早写的会漏）。
- 跳转长流程在界面里会不会太长难读；往回跳的观感。
- 独立逻辑和条目同场时，提示词顺序是否符合预期。
- 手机端逻辑编辑页的滚动与按钮大小。

## 11 · 进展（2026-10-25，v0.10.0）

- **随机数节点**：流程里能掷骰子；按"楼层 + 节点"取种子，同一条消息重画结果不变，下一楼才换；可选整数、是否存进聊天。
