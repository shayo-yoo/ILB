## 2. 通用步骤

1. 备份一次数据：书架 →「导出全部数据」，存好 `ilb-backup.json`。
2. 打开 ILB 面板，确认七页都能进、当前版本号在设置页能看到。
3. 按下面分组逐条测；每条只做一件事，测完立刻记结果。
4. 出问题时记下：哪一页、点了什么、看到什么、预期什么；能截图就截图。
5. 全部测完，把「结论」一节填上，再把这份文件或截图发回来。

**探针查出的真 bug（已修，v0.19.1）**：`ui/shell.js` 在手机布局分支调了 `desktop.closeForce()`，
但 `ui/floating.js` 只导出 `close(force)`。结果在真实手机尺寸下整套界面挂不上（假 DOM 默认 1280 宽，
永远走桌面分支，所以单元与冒烟都没发现）。修复为 `desktop.close(true)`，并补了一条「手机布局」冒烟步。

**第五轮查出的第二个真 bug（已修，v0.19.3）**：`ui/guard.js` 在桌面端把「有未保存的修改」确认层
挂进了关着的 `<dialog class="ilb-m">`（桌面端这个对话框也存在、只是 `display:none`），整层变成 0×0——
拦截逻辑在跑，但用户什么都看不到。修复为只在 dialog 真的打开时才挂它，否则挂 body；判断抽成
`hostFor(doc)` 并补了单测。

**第七轮查出的第三个真 bug（用户报告，已修，v0.19.5）**：电脑端规则卡的「⋯」菜单默认就摊开、
几张卡互相压。菜单带着 `hidden`，但 CSS 给 `.ilb-menu` 写了 `display:flex`——作者样式会盖过浏览器
给 `[hidden]` 的 `display:none`，假 DOM 不跑 CSS 所以没发现。修复为在 ILB 容器内统一
`[hidden] { display: none !important; }`，并让「打开一个先收别的」「点别处全收」。同一坑波及
导航「更多」下拉、筛选抽屉、试运行结果框，一并验证。

**第十轮顺带查出的第四个视觉 bug（已修，v0.21.3）**：给 B5 截图时发现浮窗是半透明的，
底下的聊天正文透上来，白底上的深字和聊天字叠在一起很难认。根因是宿主主题的
`--SmartThemeBlurTintColor` 本身带 0.82 透明度，酒馆自己的面板靠 `backdrop-filter:
blur(var(--SmartThemeBlurStrength))` 补实，而这个主题的 `--blurStrength` 是 `0`。
修复为把同一层 tint 在窗子底上叠两遍（颜色不变，不透明度约 0.97），并加单测守住写法。

**第十轮（v0.21.4）查出的第五个真 bug**：紧凑宽度（窗宽 < 560）下导航折成下拉，但下拉的 option 值是「书架」「逻辑」这些文字——
`nav.js` 的模型给的是 `{ id, label }`，`selectBox` 要的是 `{ value, label }`，中间没翻译。选中后 `onChange`
拿到中文标签，`setTab(「逻辑」)` 找不到页面，静默不切。修复为在 `panel.js` 翻译，并在冒烟里断言 option 值是页面 id。
