# 世界书接口（ILB.api，1.4）

给别的扩展用。只走这一层，不要直接读 `ILB.repository`——内部结构会变。

## 就绪

```js
const api = globalThis.ILB?.api ?? (globalThis.ILB_READY ? await globalThis.ILB_READY : null);
if (!api) throw new Error('没有 ILB');
await api.ready;
if (!api.caps.includes('worldbooks')) throw new Error('ILB 版本太旧');
```

## 方法

| 方法 | 返回 |
|---|---|
| `worldbooks.list({detail})` | `{ok, books:[{id,name,enabled,entries,logics,updatedAt,schemaVersion, book?}]}` |
| `worldbooks.get(id)` | `{ok, book}` / `NOT_FOUND` |
| `worldbooks.has(id)` | `{ok, exists}` |
| `worldbooks.exportBook(id)` | `{ok, schema_version, exported_at, book}` |
| `worldbooks.importBook(payload, {onConflict, targetId})` | `{ok, id, action:'created'｜'skipped'｜'overwritten'}` |
| `worldbooks.importMany({books}, opts)` | `{ok, imported:[{index,id,action}], failed:[{index,error}]}` |
| `worldbooks.deleteBook(id, {cascade})` | `{ok, id, removedBindings}` / `CONFLICT` |

`payload` 可以是 `{book}` 或书本身；冲突策略：

- `new`（默认新建 id，不覆盖任何已有书）
- `skip`（已存在就跳过，返回原 id）
- `overwrite`（用导入内容替换，保留原 id 与创建时间）
- `ask`（默认；返回 `CONFLICT`，带 `error.id` 与 `error.message`）

## 导入时的版本校验（1.4 新增）

`payload.schema_version`（或 `payload.book.schema_version`）决定这本书能不能直接进来：

| 声明版本 | 行为 |
|---|---|
| 等于当前版本（2） | 直接导入 |
| 大于当前版本 | `NOT_SUPPORTED`，提示先升级 ILB——**不猜**未来格式 |
| 小于当前版本 | 先就地迁移再导入；迁不动就 `BAD_PAYLOAD` |

`importMany` 逐本校验：失败的进 `failed[]`，不会因为一本坏了就整批拒绝。

## 删书（1.4 新增）

```js
const out = await api.worldbooks.deleteBook('book-abc');
// 还有角色卡关联着这本书时：
// { ok:false, error:{ code:'CONFLICT', message:'还有 2 个角色关联这本书', boundCount:2 } }

await api.worldbooks.deleteBook('book-abc', { cascade: true });
// { ok:true, id:'book-abc', removedBindings:2 }
```

- 默认**拒绝**删"还有角色卡关联着"的书：关联是别的扩展存的数据，不能悄悄弄断。
- `cascade:true` 才连关联一起删，`removedBindings` 告诉你连带删了几条。
- ILB 自己书架里的删除也遵守同一条规矩：确认框会写明"还有 N 个角色关联着这本书"。

## 错误

`{ ok:false, error:{ code, message } }`，不抛异常。

| code | 含义 |
|---|---|
| `NOT_FOUND` | 没有这本书 |
| `CONFLICT` | 已存在，需调用方决定策略；或删书时还有关联 |
| `BAD_PAYLOAD` | 不是有效世界书 / 批量导入不是数组 / 迁移失败 |
| `NOT_SUPPORTED` | 这一版 ILB 还没有这个方法；或书的 schema_version 比 ILB 新 |

## 注意

- 导出结果是深拷贝，改它不会影响存档。
- `new` 会换 `book_id`，并把条目/逻辑 id 前缀与流程内引用一起改写。
- 接口只增不改：`API_VERSION` 加字段不破坏旧调用；要判断能力请用 `caps`（1.4 起多了 `'bookDelete'`）。
- 角色卡 ↔ 书的关联不在这份文档里，见《UI扩展接口》第 10 节。
