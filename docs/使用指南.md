# ILB 使用说明

> 这份文件由 `extension/tests/export-guide.mjs` 从 `extension/data/guide/zh-cn.json` 生成，不要手改；改 JSON 后重跑脚本。
> 扩展里点标签栏最右边的「使用说明」看到的就是同一份内容。

ILB 是一个世界书（lorebook）控制器：它决定哪一段设定在什么时候进入提示词。这一页把「能做什么、怎么开始、每个功能在哪」一次讲清楚，不用翻文档。

## 它到底解决什么问题

原生世界书一本对话只能挂一本，触发词很死，出了问题也看不出原因。ILB 把书拆成可以随时启停的独立单位，并且把「为什么这条出现了 / 为什么没出现」记下来给你看。

- 多本书同时在场：文风、背景、角色附加设定各管各的。
- 判定说人话：什么时候出现 → 还要满足什么 → 放在哪。
- 出问题能查：诊断页逐条写清楚卡在哪一步。
- 可以让设定「有状态」：变量、字段、流程图，比如剩余抽卡次数。

## 五分钟上手

1. 打开设置页里的 ILB 卡片（或点屏幕边上的悬浮球），进「书架」。
2. 点「从原生世界书导入」，把现有的书搬进来；导入不会改动原件。
3. 到「规则」页看一眼条目：触发词、条件、位置都按卡片分好了。
4. 发一条消息，再回「诊断」页，看每条规则为什么出现或没出现。
5. 想换一套开关组合，去「快照」页存一份，以后一键切回。

> 第一次用建议先什么都别改，只发一条消息看诊断页——先建立「它在做什么」的直觉。

## 一条条目怎么才会出现

判定按固定顺序走，任何一步没过，这条就不出现：

| 步骤 | 看什么 | 在哪改 |
| --- | --- | --- |
| 书在场吗 | 手动开关 / 永远启用 / 跟随角色卡 | 书架页每本书右下角 |
| 触发 | 出现这些词 / 正则 / 一直出现 | 编辑规则 · 第一段 |
| 条件 | 文本包含 / 另一条已出现 / 变量比较 | 编辑规则 · 第二段 |
| 时效 | 延迟、持续、冷却、扫描最近几条 | 编辑规则 · 第三段 + 设置页 |
| 预算与位置 | 位置、深度、权重、概率、同组 | 编辑规则 · 第四段 + 设置页 |
| 流程图 | 画了流程就必须走通 | 编辑规则 · 判定流程 |

## 让设定「有状态」：流程图

在「编辑规则」里点「编辑流程」，用节点搭判断。不画流程的条目，行为和原生世界书一样。

| 节点 | 作用 | 例子 |
| --- | --- | --- |
| 检测 | 看词 / 正则 / 某条是否已出现 / 消息条数 / 变量 | 「提到王城」 |
| 判定 | 几条条件同时成立，或任一条成立 | 「提到王城」且「天数 > 3」 |
| 比较 | 两个值比大小 | 幸运 >= 80 |
| 定义 | 给变量起个本轮使用的名字 | 把「最近提到的地点」记成变量 |
| 计算 | 加减乘除、取最大最小 | 抽卡次数 - 1 |
| 记住 | 把值写进聊天变量，下一轮还在 | 剩余次数 - 1 存起来 |
| 激活条目 | 直接拉另一条参与这一轮，不用等它的触发词 | 抽卡 → 卡池 |
| 添加 | 成立时额外加一句正文 | 「次数不够了。」 |
| 通过 / 不通过 | 结束判断 | — |

> 「激活条目」默认只连锁 2 层（设置页可改，0–5），同一条同一轮只激活一次，所以不会死循环。

## 变量和宏

聊天变量是「这一场对话里一直记着的小纸条」。流程图的「记住」会写它，「状态」页可以手动加、改、删。

- 在条目正文里写 {{ILB:名字}}，注入时换成当前值；名字不存在就留原样，方便你发现拼错。
- 内置的 {{user}} / {{char}} 等照常能用；ILB 只认 {{ILB:...}} 这一种前缀，不抢别家的宏。
- 「计算」默认只影响本轮，勾「存进聊天」才会下一轮还在。
- 变量跟着聊天走，换聊天不会串。

## 动态条目：让一条设定自带数字

在规则编辑器里给条目加「字段」，它就有了自己的数值；「状态」页会按字段类型生成控件，不用写宏。

| 类型 | 长什么样 | 适合 |
| --- | --- | --- |
| 数字 | 输入框，可设最小/最大/步长 | 剩余次数、好感度、天数 |
| 开关 | 勾选框 | 某件事是否发生过 |
| 选项 | 下拉框，选项自己填 | 天气、季节、当前阶段 |
| 文本 | 一行输入框 | 名字、地点 |

> 字段名就是变量名，所以流程图、宏、条件都能直接用它。最多 12 个字段。

## 让逻辑不靠条目也能跑（v0.9.0）

以前逻辑只能挂在世界书条目上：先命中触发词，条目出现，才轮到它的流程。现在每本书还能放"独立逻辑"——它自己带触发词，命中就直接跑，不需要任何条目先出现。

- 在哪：规则页最下面「独立逻辑」一栏，点「新增逻辑」。
- 它和条目的区别：条目决定"这段设定进不进提示词"，逻辑决定"这段计算/判断跑不跑"。
- 能干什么：判断楼层数（条件里选"消息数"）、判断 AI 回复里有没有某个词、改变量、"说一句"把结果写进提示词、点名带出别的条目或逻辑。
- 不写触发词的逻辑不会自己跑，只等流程里「调用逻辑」叫它，或者「激活条目」点名。

> 同一段内容既可以写成条目也可以写成逻辑。这不是重复设计：条目适合"给人看的设定"，逻辑适合"要算的东西"。两套触发都保留，按场景挑。

## 掷骰子、每轮都跑、逻辑单独一页（v0.10.0）

逻辑已经从规则页挪到单独的「逻辑」页。流程里多了一个「随机数」节点；逻辑和条目都能选"什么时候跑"，初始化一类的逻辑不用再靠触发词。

- 随机数：写变量名、范围和是否整数。它按"楼层"取种子——同一条消息重画多少次都是同一个数，换下一楼才重新掷。想每轮重掷就不勾"存进聊天"。
- 什么时候跑：默认"看触发词"；选"每轮都跑"就不看词，适合初始化；选"每次 AI 回复后 / 用户发言后"只在相应回合跑。
- "每轮都跑"每次都跑，要只做一次就在流程里用变量判断（比如 未初始化 = 1 时初始化，然后把 未初始化 设成 0）。
- 「逻辑」页：新建、编辑、试一句、启停、单条导出、删除，以及整本导入导出。规则页底部留了一句提示。

## 流程里跳来跳去、复用别的逻辑

流程编辑器多了两个节点：「跳转」和「调用逻辑」。

| 节点 | 怎么用 | 注意 |
| --- | --- | --- |
| 跳转 | 填要跳到的节点 id，设置"最多跳几次"和"超了怎么办" | 允许往回跳；次数用完按你选的"终止"或"从下一条继续" |
| 调用逻辑 | 选一条独立逻辑，把它当子步骤跑 | 被调用的逻辑里"记住"的值会带回来；它不通过会让整条流程不通过 |

> 复制一个步骤再粘贴，会得到一份新的、和原来互不影响的副本（节点 id 会重新生成）。

## 让 AI 主动调用逻辑（默认关闭）

打开设置页「AI 调用逻辑」之后，AI 在回复里写 [[ILB:扣款(3)]] 这样的标记，就会真的去跑那条叫「扣款」的逻辑。

- 只有你在逻辑编辑页勾了"允许 AI 调用"、并写好参数名的逻辑，才会被执行；没开放的名字会被拒绝。
- AI 只能改聊天变量（数字、文本），改不了 SillyTavern 或扩展本身的设置——它不是 agent，只是会调用工具的对话模型。
- 每轮最多调用几次、往回看几条 AI 消息，都在设置页里调。
- 成功和失败都会记在诊断页，拒绝原因写人话。
- 同一条消息里的同一个调用只执行一次——重画、刷新、编辑都不会让它再扣一次钱。

> 默认关闭。关着的时候，AI 写出来的 [[ILB:…]] 只是一段普通文字，不会产生任何效果。

## 流程也能写成文字（v0.13.0）

判定流程有两种写法，改的是同一份流程，随你高兴换着用：表单是一块一块搭，文本是一行一步地写。表单适合慢慢挑，文本适合一次写一长串、或者让 AI 帮你写。

1. 打开规则编辑器，点「编辑流程」，在流程区域的右上角点「文本模式」。
2. 你会看到刚才表单里搭的东西被写成了文字，一行一个步骤。
3. 直接改文字。看不懂的行会当场列出来，「第几行、为什么」，改好就没了。
4. 点「收下这段文本」存进节点树；点「切回表单」回到一块一块的界面。

- 值有三种写法：$变量、数字 12、"文字"。
- 引用一律写名字（#条目名、>逻辑名），找不到会告诉你"是不是想写某某"。
- 这不是一门编程语言：能用的词是固定的那几个，写别的就是"看不懂的行"，不会猜。

| 你想干什么 | 就这么写 |
| --- | --- |
| 检测一段话里有没有某个词 | 检测 包含 "抽卡" 在最近3条 |
| 判断变量大小 | 比较 $抽卡次数 > 0 |
| 做算术并存起来 | 计算 $抽卡次数 = $抽卡次数 - 1 [存] |
| 让某个条目出场 | 激活 #铜钥匙 |
| 点名另一条逻辑来跑 | 调用 >结算 |
| 跳到本流程的第几步 | 跳转 @2✓.1 |
| 缩进两格 = 属于上面那一支 | 先写「成立」/「不成立」，下一行缩进两格 |

> 文本里写的是「第几步」而不是节点编号，所以搬回来之后节点会换新编号，但「跳转」仍然指着同一个地方。

## 手机和电脑

两边是两套壳，功能一样，位置不同。

- 电脑：点屏幕边上的悬浮球打开浮窗，可拖动；Esc 或 × 关闭。
- 手机：浮窗铺满整屏；顶部有一条变量坞，显示前 3 个变量，点一下进「状态」页。
- 两边每个页面右上角都有「?」，写着这一页是干什么的。
- 标签栏最右边的「使用说明」随时能回到这一页。

## 数据存在哪、怎么搬走

- 书、规则、设置存在 SillyTavern 的扩展设置里；变量和字段值存在当前聊天的状态里。
- 换聊天 = 换一套变量；书和规则是全局的，不会跟着聊天跑。
- 设置页可以整体导出/导入 JSON，换电脑、备份、分享都用它。
- 导入原生世界书是「复制一份」，不会改你的原件；重导只更新没被你改过正文的条目。

## 常见困惑

- 「写了却没出现」→ 去诊断页看卡在哪一步，通常是触发词没命中、条件不满足，或超出预算。
- 「很久以前提过的词不触发」→ 设置页「扫描最近几条消息」默认只看最近 3 条，调大即可。
- 「它把正文改了吗」→ 没有。ILB 只决定注入什么，不写你的聊天记录，也不改世界书原文。
- 「关掉总开关会怎样」→ 完全不注入，但书、规则、变量都还在，打开就恢复。
- 「流程图会不会很慢」→ 纯本地计算，一条流程几十个节点也是毫秒级；慢的是模型，不是它。

## 它不做什么

- 不替你写设定，也不判断设定好不好——它只按你写的规则执行。
- 不维护「事件系统」：没有事件队列、没有触发器链、没有自动剧情推进。
- 不解析自然语言指令：模型写的事实标记有限，写错会退化成普通文字。
- 真实 SillyTavern 的端到端表现仍在验证中（作者当前无法真机测试），遇到异常请看控制台 [ILB] 开头的日志。
