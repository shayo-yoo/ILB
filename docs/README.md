# 文档怎么读

这个目录放的是**开发文档**，不是给使用者看的说明书。第一次接触项目，建议按下面的顺序读。

| 文件 | 什么时候读 | 一句话 |
| --- | --- | --- |
| [参考文档.md](参考文档.md) | 想知道"应该怎么实现、什么算做错" | 完整规格：数据模型、判定顺序、注入、界面约束、验收清单。编号形如 `ILB-4.10.3`，代码里的注释会引用这些编号 |
| [开发说明.md](开发说明.md) | 想动代码 | 模块职责表、低耦合约定、测试命令、已知未完成 |
| [决策记录.md](决策记录.md) | 想知道"为什么是这样" | 每条重要选择的背景、决定、否决的方案与理由（D-0001 起） |
| [CHANGELOG.md](CHANGELOG.md) | 想知道"哪一次改了什么" | 只追加、按时间倒序，每次改动都写清新增/修订/修正/待验证 |
| [留痕规范.md](留痕规范.md) | 想参与维护 | 这个项目的改动怎么记录：编号规则、状态标记、什么必须写决策记录 |
| [历史/参考文档-v1.0.md](历史/参考文档-v1.0.md) | 想看最初的设计稿 | 第一版文档的结构快照。**已作废**，只用于追溯 |

## 三条读文档时要知道的约定

1. **规格与代码不一致时，以规格为准**（规格是验收依据），并把差异记进 `CHANGELOG.md`。
2. **没有写在规格里的"聪明做法"，默认视为不该做**。想加，先改规格并写决策记录。
3. **状态标记**：`✅` 已确定 / `🔧` 实现中或未验证 / `⚠️` 已废弃（会写明被谁替代）。

## 改文档的规矩

- **改了规格，就要同时更新 `CHANGELOG.md`**——否则下一个人无法知道"什么时候、为什么"变的。
- **换了做法，就要在 `决策记录.md` 里加一条 D-xxxx**，写清否决了什么、为什么否决。只写"决定了 X"的决策记录没有价值。
- **不要删除旧条目**。写错了就再写一条"更正"，保留原来的错误——错误的痕迹本身是信息。
