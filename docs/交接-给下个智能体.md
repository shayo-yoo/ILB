# 交接：给下一个智能体（接手 ILB 本身）

> **只想做 UI 扩展？别读这份。** 看 `docs/交接-UI扩展.md`：那里只讲接口与工作方式，不需要理解 ILB 内部。
> 本文档面向"要改 ILB 本体"的人。

> 写于 2026-10-25，最后由 v0.15.0（2026-10-31）更新。目标：你不需要读完整部历史，也能安全地改这个项目。
> 先看 `docs/文档地图.md`；需要背景时看 `docs/history/早期阶段摘要.md`；要改行为时查 `参考文档.md` 的对应编号。

## 1. 这是什么

SillyTavern 的第三方扩展 **Independent Lorebook（ILB，独立世界书）**：

- 给用户：多本世界书同时生效、每本书可随时启停、逐条解释"为什么这条出现了/没出现"。
- 给设定：条目可以有状态（变量、动态字段、流程图），能掷骰子、能互相点名、能被独立逻辑调用。
- 边界：**不是 agent**。AI 只能通过正文里的 `[[ILB:名字(参数)]]` 在"白名单 + 默认关闭 + 幂等"的前提下改变量，碰不到 SillyTavern 与扩展配置。

用户是非技术背景的中文用户，重视"看得懂、能回退、失败要出声"。所有面向用户的文案用中文，避免术语堆叠。

## 3. 命令

全部在 `extension/` 下执行：

```powershell
node --test tests/*.test.mjs          # 单元测试（不要用 node --test tests/，部分 Node 版本会失败）
node tests/linkcheck.mjs              # 模块能否解析、import 是否存在
node tests/smoke-dom.mjs              # 假 DOM 界面冒烟
node tests/export-guide.mjs           # 由 data/guide/zh-cn.json 生成 docs/使用指南.md
node tests/gacha-demo.mjs             # 抽卡场景演示（验收用，不是单测）
node tests/logic-demo.mjs             # 独立逻辑 / AI 调用演示
node tests/serve.mjs 8799             # 起本地静态服务，浏览器打开 tests/*-probe.html 可跑探针
```

PowerShell 下 `node ... 2>&1 | Select-String` 会把 stderr 变成 `NativeCommandError`、显示 exit 1；判断成败看输出里的"失败 0"，不要只看退出码。

## 4. 铁律（违反会出真问题）

1. **中文文件只用 `edit` / `write` 工具，或 node `fs.readFileSync/writeFileSync(...,'utf8')`**。PowerShell 5.1 的 `Get-Content | Set-Content` 会把无 BOM UTF-8 当 GBK 写坏（v0.6.1 真出过事故，靠镜像恢复）。
2. **`extension/manifest.json` 只声明 `index.js`**；其它模块靠 import。加文件不用改 manifest，但要能被 linkcheck 追到。
3. **新功能默认关闭，且关掉时与旧版本行为完全一致**。AI 调用、独立逻辑、酒馆联动（`hostLinkEnabled`）都遵守这条。
4. **失败必须看得见**：用户可见的失败给一句人话 + 诊断页有一行；不许静默 catch 掉。
5. **状态必须可重放**：任何"记进聊天"的值都要能从聊天记录推出来；随机数用楼层种子，不要 `Math.random()`。
6. **算不出来就说算不出来**：表达式/模板取不到变量时不要 `|| 0`、不要 `?? ''`，返回 `{ok:false,error}` 并写进步骤日志（`evalOperand` 的约定）。
7. **不认识的节点原样保留**：`normalizeNode` 标 `unknown:true`，不许降级成 `test` 或丢字段（ILB-7.16）。
8. **文档编号只增不改**：`参考文档.md` 的 `ILB-x.y.z` 不复用；废弃标 ⛔ 并写替代编号。`CHANGELOG.md` 只追加。换了做法就在 `docs/决策记录.md` 写 `D-xxxx`，必须写"否决了什么、代价是什么"。
9. **不要碰宿主**：所有宿主 API 走 `adapters/`；`core/` 必须保持纯函数、无 DOM、无网络、不读宿主全局。新来源一律进 `adapters/sillytavern-context.js`，事件一律进 `adapters/sillytavern-events.js`（别处不要再 `source.on`）。
10. **不确定就先读** `参考文档.md` 的相关编号条款（必要时读宿主源码 `D:\1\APP\SillyTavern`），再动手；别按"看起来合理"改。

## 5. 代码地图

```
extension/
  index.js              入口：装配 repository/pipeline/api/panel/shell/card + 宿主 context/watcher
  host.js               唯一 import 宿主模块的地方（getContext/getEventSource/…）
  core/                 纯函数
    model.js            书/条目/逻辑/触发器的 normalize + validate；strategyOf/legacyStrategyOf
    host-context.js     HostContext 归一化、策略/覆盖枚举、nativeKeysOf、matchBookToHost
    resolve-books.js    每本书启停判定 + 原因（details）
    evaluate.js         判定主流程：触发→条件→预算→排序→流程→逻辑→AI 调用（约 900 行，最需要小心）
    flow.js             流程节点定义、归一化、执行（条件组/随机/重复/停止）
    expr.js             表达式与模板求值（禁 eval）
    validate.js         静态验证器（与执行器分离）
    migrate.js          存档 v1→v2 迁移
    vars.js             变量归一化、宏展开、chatId
    fields.js           动态字段（key 即变量）
    calls.js            AI 正文调用解析
    settings-defaults.js 默认设置与枚举常量
  runtime/
    pipeline.js         把"快照 → resolveBooks → evaluate → 注入"串起来，落盘变量
    api.js              对外接口 v1.2
    registry.js         每场聊天/每本书的运行时状态
  adapters/
    repository.js       唯一存档入口（含迁移与快照）
    native-worlds.js    /api/worldinfo/* 只读
    sillytavern-context.js 原生世界书关联（六类来源）
    sillytavern-events.js  角色/聊天/群聊/Persona/世界书事件集中订阅
    inject.js           注入
  ui/
    panel.js            七页外壳 + 每页一句话
    view-*.js           各页（shelf/diagnostics/settings 已认识 strategy/override/details）
    flow-editor.js      流程树编辑（节点表单、添加器、条件组、验证摘要）
    logic-editor.js     逻辑编辑浮层
    editor.js           条目编辑 / 试一句
    shell.js/layout.js  电脑/手机双壳路由 + 密度/几何纯函数
    floating.js         浮窗：拖拽、缩放、最小化/最大化、data-density
    widgets.js          el/button/checkbox/field/...（没有框架，全手写 DOM）
  data/guide|help       文案（guide 生成 docs/使用指南.md）
  tests/                单测/检查/探针/演示
```

数据形状速查：

- 书：`{schema_version:2, book_id, name, activation:{mode,strategy,override,characters,manual}, host:{nativeNames,aliases,lastMatchedAt}, pool, entries[], logic[], _source}`。
- 条目：`{id,title,content,trigger{any,all,not,regex,source,meta},when[],logic:{mode,nodes},wait,timed,group,probability,injection,fields,...}`。
- 流程节点：`{kind,id,...}`；分支在 `node.then` / `node.else`，循环体在 `node.body`，条件组在 `node.when` / `condition.children`。
- 值（operand）：`{type:'var'|'number'|'text'|'template'|'expr', ...}`。
- 存档：`extension_settings.independent_lorebook`，含 `version`（= `core/migrate.js` 的 `DATA_VERSION`）、`settings`、`books`、`manualState`、`chatStates`、`importLog`、`ui`、`snapshots`、`migrationLog`。
- 设置：见 `core/settings-defaults.js` 的 `DEFAULT_SETTINGS`（`hostLinkEnabled/doubleInjectPolicy/logicEnabled/logicMaxPerTurn/aiCallsEnabled/aiCallMaxPerTurn/aiCallScan/maxActivateDepth/...`）。

## 7. 已知坑（还会踩的）

| 坑 | 对策 |
|---|---|
| 请求体里账本位置不对 | 注入深度语义：`INJECT_DEPTH=0` 才在最后一条消息之后 |
| 重画导致 AI 调用重复执行 | 一切"从最近消息里读到就执行"的动作都要幂等（参考 `__ilbCallsSeen`） |
| 元触发器把 `roleOf` 的 `'ai'` 当 `'assistant'` | 判角色用 `roleOf()`，别自己写字符串比较 |
| `describeDeclaration`/`problems` 当数字用 | 它是数组，判断 `problems.length` |
| 手机上的浮层点击穿透/看不到 | 手机壳用 `<dialog>` + `showModal()`；新浮层要挂到它里面 |
| 版本号写三处 | `index.js VERSION`、`manifest.json version`、必要时 `MOBILE_SKIN_VERSION` |
| 镜像里的 `docs/参考文档.md` 不更新 | `robocopy` 不覆盖时间戳更旧的大文件，用 `Copy-Item -Force` 后 `Get-FileHash` 比对 |
| 提交消息带 BOM | 用 node 写消息文件，别用 `Set-Content` |
| `resolveBooks` 的 `activeBooks`/`inactiveBooks` 是 **id 字符串数组** | 要书名就自己用 `listBooks()` 建 Map，别当对象取 `.name` |
| `resolveBooks` 的 `warnings` 是 `[{bookId,message}]` | 不是字符串数组，渲染时要取 `.message` |
| 假 DOM 不实现 `disabled` 的原生拦截 | 按钮禁用之外，回调里必须再判一次（文本模式只读就踩过） |
| `import()` 宿主模块可能失败 | 只在 `adapters/` 里试，失败要落到 `unsupported` + 一句人话，不要读 DOM 猜 |
| 事件名在新宿主里可能没有 | 一律 `eventTypes.X ?? '名字'`，`source.on` 失败要记 `failures` 而不是抛 |
| 同一个 `grep`/正则不认 `\p{L}` | Node 24 支持；但 `tokenize` 里名字要按 Unicode 属性写，别写 `[A-Za-z]` |

## 8. 下一阶段（UI 扩展）

已定方案：`docs/下一阶段-UI扩展方案.md`。

- P0（**已完成**）：ILB 侧对外接口（v1.0 起，现 1.2）。
- P1：独立仓库的 UI 扩展骨架，只读面板（读 `snapshot()` 渲染变量卡）。
- P2：控件动作 `set / call / openPanel`。
- P3：网格声明编辑器（`cols/rows/gap/cell` + `widgets[].area`，用区域而非绝对坐标）。
- P4：声明导入导出、预设。
- P5：手机主题、无障碍。

UI 扩展只依赖 `window.ILB.api`，**不要** import ILB 的内部模块；ILB 也不要为了 UI 扩展往内部加"特例字段"。
