# Independent Lorebook (ILB)

[![checks](https://github.com/shayo-yoo/ILB/actions/workflows/checks.yml/badge.svg)](https://github.com/shayo-yoo/ILB/actions/workflows/checks.yml)
[![license](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

给 [SillyTavern](https://github.com/SillyTavern/SillyTavern) 的世界书加两样东西：**一条可以自己搭的判定流程**，和**多本世界书的管理方式**。全程不需要写任何语法。

> 状态：**早期版本**。扩展能在 SillyTavern 中加载、能导入原生世界书；核心判定逻辑有 102 个单元测试（全过）。但注入效果、手机端布局、不同主题下的显示仍需要更多实机验证。详见 [已知限制](#已知限制)。

---

## 它想解决什么

原生世界书靠"关键词出现就注入"工作，够用，但有三处会让人别扭：

1. **判定太钝**。你只能表达"这句话里有『王城』"。想表达"提到王城、而且最近聊到过钟声、而且已经聊了三天以上"，就只能再写一条常驻条目，或者干脆放弃。
2. **书多了就乱**。一本文风指导、一本背景设定、一本第三方设定，各自该在什么时候生效，原生只能靠角色卡绑一本书，或者靠关键词互相干扰。
3. **坏了不知道为什么**。规则没出现，你只能猜是触发词写错、还是被概率挡了、还是被别的条目挤掉了。

ILB 分别对应三件事：**节点式判定**、**多书启用与总条目池**、**每条规则都能当场"试一句"**。

## 功能

- **多本世界书并存**：每本书有「启用方式」（永远 / 跟着角色卡 / 手动）和「是否进公共池」两个开关。逻辑可以从所有书的**总条目池**里挑条目，不局限在同一本。
- **判定流程（可选）**：在关键词之上叠一棵节点树——检测、判定、比较、定义、计算、添加、通过、不通过。**不画流程时，行为与原生世界书一致。**
- **试一句**：任何一条规则都能就地输入一句话，逐步显示"触发词过了没有、条件过了没有、流程走到哪一步被拦下"。
- **诊断**：每一轮生成后，能说清哪些条目出现了、哪些没出现、卡在哪一步。
- **搜索与筛选**：书架、规则、导入选择三处都能按名称 / 正文 / 分组 / 触发词搜索，支持多词（同时包含）与按状态筛选。
- **快照**：把"现在哪些条目是开的"存成一份快照，随时切回某个风格组合；只记开关，不动正文。
- **批量操作**：勾选只作用于当前筛选结果，可批量启用 / 停用 / 设为常驻。
- **导入原生世界书**：单本或一键全部；四种"条目开关"处理方式（保留原样 / 全部开启 / 全部关闭 / 每次问我）；重复导入是合并而不是多出一本。
- **两种界面**：设置页只留一张小卡片，其余功能在右下角悬浮球打开的浮窗里；电脑可拖可缩放，手机整屏。

## 安装

### 方式一：用 git（推荐，便于更新）

```bash
cd SillyTavern/public/scripts/extensions/third-party
git clone https://github.com/shayo-yoo/ILB.git ILB
```

更新时进这个目录 `git pull`，然后刷新页面即可。

### 方式二：下载压缩包

1. 在 GitHub 页面点 **Code → Download ZIP**；
2. 解压后把里面的文件夹改名为 `ILB`，放进
   `SillyTavern/public/scripts/extensions/third-party/`；
3. 确认路径最终长这样：`.../third-party/ILB/manifest.json`（`manifest.json` 必须在这一层，不能多套一层文件夹）。

然后**刷新 SillyTavern 页面**。右侧扩展栏里会出现这张卡片，屏幕右下角出现一个悬浮球。

如果什么都没出现，按 F12 打开控制台看有没有 `[ILB]` 开头的日志；没有的话多半是目录层级放错了。

## 第一次使用

1. **导入一本书**：点悬浮球 → 「书架」→「导入原生世界书」→ 选一本已有的书。
2. **看一条规则**：切到「规则」→ 点某条规则的「编辑」。第一段就是「什么时候出现」，第三段是「判定流程」。
3. **验一下**：点「试一句」，输入一句话，看它一步步的结论。
4. **发一条消息**：回到聊天，发一句含关键词的话，再打开「诊断」，应该能看到这条规则为什么出现。

## 判定流程长什么样

以一个"夜里王城的钟声"为例，想在「提到王城 + 最近 5 条里有钟声 + 对话已经进行了一会」时才出现，可以这样搭：

```
检测：最近 5 条里有「钟声」
├─ ✓ 成立时
│   比较：messageCount >= 3
│   ├─ ✓ 成立时 → 通过（结束）
│   └─ ✗ 不成立时 → 不通过（结束）
└─ ✗ 不成立时
     → 不通过（结束）
```

可用的节点：

| 节点 | 它做什么 |
| --- | --- |
| 检测 | 看某个词 / 正则是否出现、某条规则是否已经出现、消息条数、变量的值 |
| 判定 | 把多条「检测」组合起来：全部成立，或任意一个成立 |
| 比较 | 两个值比大小（能当数字就按数字比，否则按文本比） |
| 定义 | 给变量起个名字（只在这一次判定里有效） |
| 计算 | 加减乘除、取最大最小 |
| 添加 | 成立时，往这条规则的正文后面再补一句 |
| 通过 / 不通过 | 立刻结束整条流程 |

两个要点：

- **「不成立时」留空 = 这条规则不出现**。想让它继续，就在里面放一个「通过（结束）」。
- 默认模式是「关键词满足后，再走流程」；想完全用流程控制，把模式切到「只看流程」。

## 已知限制

诚实地列在这里，比藏在文档角落有用：

- **没有在真实对话里做完整回归**：判定层有单元测试，界面有假 DOM 冒烟测试，但"注入是否真的进了提示词、位置/深度/角色的实际效果"仍需实机确认。
- **手机端已经试过一轮**（2026-10-23：发现并修掉了"次级菜单太靠上、关闭按钮点不到"；10-24 又修掉了"浮层只剩很薄一排"），但机型覆盖仍然只有一台，横屏与平板未验证。手机端如果是 SillyDroid 这类 WebView 客户端，布局判定走的是"宽度 + 是否触屏"，可能与真实机型的观感有差异。
- **群聊场景**（一个聊天里有多个角色）尚未处理。
- **流程的变量不跨轮保存**，只在"这一条规则这一次执行"内有效。
- **"AI 帮你把一句话变成规则"** 还没有做，目前只有本地结构检查。
- 保存是去抖的：改完设置立刻刷新页面，最后一次改动可能丢。

## 点了按钮没反应？先做这三步

这类问题最常见的原因不是代码坏了，而是**浏览器还在用旧的 CSS**（你只覆盖了部分文件，或者刷新时命中了缓存）。按顺序做：

1. **强制刷新**：Windows 上 `Ctrl + Shift + R`，Mac 上 `Cmd + Shift + R`。
2. **运行自检**：打开悬浮球 → 设置 → 最下面「出问题时」→ 点「运行自检」。它会逐项告出"样式表有没有加载、浮层规则有没有生效、浮层能不能真的开出来、关闭按钮在不在、扩展有没有就绪"。
3. **把结果发我**：自检结果可以整段选中复制；如果控制台里有红色报错，一并附上。

正常应该看到：每次打开浮层，控制台有一行 `[ILB] 浮层已打开：<标题>`；自检里除了"未加载宿主"那几条（只有装上 SillyTavern 才会有），其余都是 ✓。

如果浮层**弹出来了、但只有顶上很薄的一排**（手机上遇到过），那是手机客户端按"桌面宽度"排版、加上内容还没到导致的。0.4.6 起有两道保险：`body` 会被打上 `ilb-mobile` 类走手机布局；打开后还会实测一次高度，太扁就自己撑起来并写明原因。控制台里若出现 `[ILB] 浮层太扁` 或 `[ILB] 浮层打开了，但正文是空的`，把那两行发我即可——它们带着量到的数值。

## 开发

代码是纯 ESM，**没有构建步骤**，直接放进 SillyTavern 就能加载。

```bash
# 单元测试（102 个）
node --test tests/core.test.mjs tests/flow.test.mjs tests/search.test.mjs \
  tests/snapshot.test.mjs tests/import-plan.test.mjs tests/ui-layout.test.mjs

# 模块链接检查：每个模块都能被加载
node tests/linkcheck.mjs

# 界面冒烟：用假 DOM 把主要界面点一遍
node tests/smoke-dom.mjs
```

判定层（`core/`）是纯函数，不碰宿主、不碰 DOM、不读存档，所以可以脱离 SillyTavern 单独测试。只有 `host.js` 一个文件认识 SillyTavern。
