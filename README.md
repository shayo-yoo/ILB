# Independent Lorebook (ILB)

让 SillyTavern 的世界书更强，同时不逼用户学语法。

> **重要声明**：这份代码**还没有在真实的 SillyTavern 里运行过**。判定层的单元测试、
> 模块链接检查、以及用假 DOM 做的界面冒烟已经跑过并通过（见 §测试），但宿主 API、
> 注入效果、真实浏览器里的样式都仍是推断。第一件事请按 §「第一步：探针」做完再判断能用不能用。

## 安装

把整个 `extension/` 目录复制到 SillyTavern 的第三方扩展目录：

```
SillyTavern/public/scripts/extensions/third-party/ILB/
```

重启或刷新页面，会出现两处东西：

1. 「扩展」设置区里一张小卡片：`世界书 · ILB`（总开关、两个常用数字、打开按钮）
2. 页面右下角一个圆形的「书」字悬浮球

**书架、规则、快照、诊断、设置五页都在悬浮球里**，点一下打开浮窗。设置页里只留最常改的几项，这是有意为之：
改规则是高频动作，不该每次都翻进设置页（见 `docs/决策记录.md` D-0019）。

## 第一步：探针（Phase 0）

打开浏览器控制台，看有没有这一行：

```
[ILB] 已启动 v0.4.8（通过 ../../extensions.js , ../../../../script.js 拿到宿主；界面：悬浮球）
```

括号里会写出这次实际命中哪几个路径、以及界面是哪一种。如果写着 `界面：退回设置页`，说明浮窗没挂上，
那时悬浮球不会出现，但你仍能在设置页里看到五个面板——这是有意设计的退化路径。

然后发一条消息，点悬浮球打开「诊断」标签。如果那里能写出"每条规则为什么出现/没出现"，说明
判定链路是通的；如果空白或报错，请把控制台的报错原样记下来。

**判定逻辑在哪里**：打开「规则」标签，每条规则的「编辑」里第一段就是"什么时候出现"（触发词 /
正则 / 常驻 + 第二组触发词）。改完不必保存也能先点「试一句」，它会把每一步的通过情况列出来。

`window.ILB` 暴露了 `registry / repository / pipeline / host / panel / floating`，排障时可以直接在
控制台查看 `ILB.describeLastRun()` 与 `ILB.describeUi()`。

**别跳过这一条**：在面板里随便改一个设置，等两秒，刷新页面，看设置还在不在。SillyTavern 不会
替扩展自动保存，是扩展自己叫宿主的 `saveSettingsDebounced`（见 `host.js` 的 `saveSettings`）。
如果这一步失败，界面看起来一切正常，但所有改动刷新即消失。

## 这个版本做了什么

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 纯数据模型 | `core/model.js` | 归一化、默认值、结构校验 |
| 判定层 | `core/evaluate.js` | 触发 → 条件 → 流程 → 时效 → 连锁 → 概率 → 分组 → 排序 → 预算 |
| 判定流程 | `core/flow.js` | 八种节点（检测/判定/比较/定义/计算/添加/通过/不通过）的纯函数执行器；**空流程等于没有流程** |
| 多书解析 | `core/resolve-books.js` | 这一轮哪些书在场、哪些条目进总池 |
| 导入导出 | `core/import-native.js` / `core/export-native.js` | 原生格式双向转换，未知字段无损暂存 |
| 重复导入合并 | `core/merge-book.js` | 按源文件 uid 配对：只增只更新、保留用户改过的正文、保留书的启用设置 |
| 纯文本工具 | `core/text-match.js` / `core/ids.js` / `core/budget.js` | 匹配、哈希、词数估算 |
| 搜索与筛选 | `core/search.js` | 多词 AND、搜正文/分组/触发词、按状态与分组过滤 |
| 快照 | `core/snapshot.js` | 只记"哪些条目开着"，不记正文；常用 10 / 临时 5，超限按最近使用淘汰 |
| 导入计划 | `core/import-plan.js` | 四档开/关策略、按来源文件判重、一键导入只导新书 |
| 宿主适配 | `host.js` | **唯一** import 宿主代码的文件；多候选路径探测 + 落盘 |
| 数据端口 | `adapters/repository.js` | 存在 `extension_settings.independent_lorebook`，每次写完通知宿主保存 |
| 原生书读取 | `adapters/native-worlds.js` | 只读 `/api/worldinfo/list` 与 `/get` |
| 注入端口 | `adapters/inject.js` | `setExtensionPrompt`，按位置/深度/角色合并 |
| 编排 | `runtime/pipeline.js` | 唯一懂执行顺序的地方，每步独立 try/catch |
| 扩展点 | `runtime/registry.js` | 新增能力注册在这里，而不是改旧文件 |
| 界面外壳 | `ui/floating.js` | 悬浮球 + 浮窗：开关、拖动、尺寸记忆、Esc、手机整屏 |
| 设置卡片 | `ui/settings-card.js` | 设置页里那张小卡片，只放最常改的几项 |
| 布局计算 | `ui/layout.js` | 纯函数：判 PC/手机、算窗口与球的位置、防越界 |
| 界面公共件 | `ui/dom.js` / `ui/help.js` / `ui/widgets.js` | 造元素、帮助浮层、控件工厂 |
| 面板路由 | `ui/panel.js` | 只负责切标签与提供 `ctx`，一页坏了只坏一页 |
| 五个页面 | `ui/view-shelf.js` / `view-rules.js` / `view-snapshots.js` / `view-diagnostics.js` / `view-settings.js` | 书架 / 规则 / 快照 / 诊断 / 设置 |
| 编辑器 | `ui/editor.js` | 四段式规则编辑 + 「试一句」预演 + 「判定流程」原地展开 |
| 流程编辑器 | `ui/flow-editor.js` | 树形节点编辑（不是连线画布），手机上不横滑 |
| 导入界面 | `ui/importer.js` | 批量导入、选择浮层、导入结果报告 |
| 自检 | `ui/selftest.js` | 一键回答"哪一环断了"：样式表、浮层规则、浮层能否开出来、扩展是否就绪 |
| 浏览器探针 | `tests/browser-probe.html` | 用真实 Chrome 量浮层矩形与关闭按钮，布局结论不靠推断 |

## 低耦合是怎么落实的

1. **只能有一个文件认识宿主**：`host.js`。换宿主、换事件名，只改它。
2. **每个外部依赖都是"端口 + 默认实现"**：数据、注入、原生书读取各自一个适配器，换实现
   不影响判定层。
3. **判定层是纯函数**：`core/` 下所有文件不 import 宿主、不碰 DOM、不读写存储。给它一个
   快照就出结果，所以能直接跑单元测试。
4. **扩展点优先于修改**：`registry.activationProviders` 等槽位留好了，新功能注册进去就行。
5. **失败隔离**：管线每一步单独 try/catch，任何一步炸了只会导致这一轮零注入，界面照常可用。
6. **外壳与内容分离**：浮窗只负责"在哪显示"，面板只负责"显示什么"。所以换入口（浮窗/侧栏/设置页）
   不用改面板；面板挂了也不会让悬浮球消失。

## 新增一个功能的标准动作

1. 写一个新文件（或新槽位实现）。
2. 在 `index.js` 里注册，不改任何已有判定代码。
3. 如果它需要新的判定输入，扩展 `EvalRequest`，然后在 `core/evaluate.js` 里加一步。
4. 补一个测试用例，并在 `CHANGELOG.md` 记一行。

## 测试

```bash
cd extension

# 1) 纯逻辑单元测试（127 个）
node --test tests/core.test.mjs tests/flow.test.mjs tests/search.test.mjs \
  tests/snapshot.test.mjs tests/import-plan.test.mjs tests/ui-layout.test.mjs \
  tests/narrative.test.mjs tests/narrative-plan.test.mjs

# 2) 链接检查：每个模块都能被加载（能抓出"导入了不存在的名字"这类错）
node tests/linkcheck.mjs

# 3) 界面冒烟：用极简 DOM 桩把面板、编辑器、流程编辑器、导入浮层、
#    设置卡片、悬浮窗、浮层结构都点一遍（只验证"不抛错"，不验证"好不好看"）
node tests/smoke-dom.mjs

# 4) 叙事引擎的端到端演示（纯 node，不需要浏览器）
node tests/narrative-demo.mjs
```

四个都通过的结果（2026-10-24 实测）：单元 127/127、链接 51 个模块全通过（**包含入口 `index.js`**）、
冒烟 19 步全过。注意这仍然**不是浏览器实测**：DOM 是假的，宿主是假的。

> **为什么链接检查一定要包含 `index.js`**：v0.4.4 曾因为一次错误的文本替换把入口写成乱码并吃掉一个引号，
> 结果整个扩展不加载（连悬浮球都没有）。当时其余检查全绿，因为它们跳过了入口。
> 现在 `linkcheck.mjs` 会给入口一个最小 `document` 桩，让 `index.js` 只被解析、不真的启动；
> 入口有语法错误会直接报 `FAIL index.js [语法错误]` 并以非零码退出。

要看"在真实浏览器里长什么样"，用静态服务器打开 `tests/browser-probe.html`

```bash
node tests/serve.mjs 8799

```

另有 `tests/empty-probe.html`：只开一层空浮层、等 800ms，单独验证"自愈有没有插入提示"（四个用例连跑时 rAF 会串扰，必须隔离验证）。

`tests/selftest-probe.html`（v0.4.7 新增）在真实浏览器里跑一遍真的 `runSelfTest()`，并额外检查"报数"的四项是否真的带数字：
规则条数、弹窗实测高度、当前布局、内联最小高度。2026-10-24 实测 PASS，输出形如
`style.css 里数到 130 条 .ilb- 规则` / `弹窗高度 162px（最小高度 160px，电脑布局）` / `已就地固定最小高度 160px`。

> **v0.4.7 的教训：兜底自己也会塌。** 用户回报浮层依旧只有很薄一排，并贴出了那层浮层的 DOM——
> 上面带着整串 `style="position: fixed; inset: 0px; …"`。这串内联样式本身就是证据：当时确实走到了
> "样式没生效 → 内联兜底"这条分支，而当年的兜底**没写 `min-height`**，所以兜底把用户送回了"一条缝"。
> 现在四条几何（`position` / `inset` / `display` / `z-index`）与弹窗 `min-height` 在打开时就内联钉死，
> 就算 `style.css` 完全没加载，浮层也铺满屏幕、弹窗也有可读高度（ILB-6.17.7）。

`tests/nocss-probe.html`（v0.4.8 新增）**故意不加载** `style.css`，用来回答"样式表没生效时，用户到底看不看得见"。
它打开一层带标题与两段正文的浮层，量浮层/弹窗的尺寸与**底色**，断言八条：铺满视口、浮层有底色、弹窗有底色、
弹窗高 ≥120、宽 ≥min(280, 视口-40)、正文文字在、关闭按钮在、控制台说明了兜底原因。
2026-10-24 实测 PASS：浮层 500×693 `rgba(0, 0, 0, 0.55)`、弹窗 500×314 `rgb(30, 30, 30)`。

> **v0.4.8 的教训："渲染出来了"不等于"看得见"。** 上一版钉死了位置与高度，用户却报"点了什么都没有"——
> 尺寸全对，但底色、边框仍来自那份没生效的样式表，屏幕上是"透明容器套透明盒子"。
> 现在打开浮层会同时检查尺寸、底色、正文三件事，任一不对就套一套**内置皮肤**（`applySkin`），
> 并且自检会报出两个底色，透明直接标红（ILB-6.18）。

## 已知未完成

- Phase 0 探针没跑过，所有 API 名称（`setExtensionPrompt` 的参数顺序、`event_types` 的字段名）
  都还需要实机确认。
- `host.js` 里的相对路径是按 SillyTavern 源码的目录结构推出来的（内置扩展在
  `public/scripts/extensions/<名字>/`，第三方在下一层 `third-party/<名字>/`，所以第三方要多走一级）。
  这是推断，不是实测。
- 保存是去抖的：改完立刻刷新页面，最后那次改动可能丢。
- 群聊场景还没处理（ILB-D1）。
- AI 体检只做了本地结构校验，模型那半还没接。
- 帮助文案写了五个面板 + 悬浮球 + 设置卡片，具体到每个控件的浮层还缺。
- 搜索、快照、批量、导入策略都是这一版新加的，**没有一个在真实环境里试过**：
  - 多词搜索的 AND 语义、搜触发词是否真的命中（正则源码也在搜索范围内）；
  - 快照恢复是否真的只改开关、不动正文；
  - 一键导入是否真的跳过已导入的书、四个数（更新/新增/保留/冲突）是否对得上；
  - 手机 375px 宽是否真的不再横滑（CSS 是推断，没有真机）。
- "试一句"与真实判定存在**已知差异**：概率、同组择一、预算、连锁四项不在预演范围内（ILB-4.9.3）。
- 判定流程是这一版新加的，**没有在真实环境里试过**：
  - 空流程是否真的与上一版逐字一致（这是硬约束，ILB-4.10.2，需要拿真实注入文本对比）；
  - 「只看流程」与连锁同时出现时，被连锁带出的规则是否按预期忽略关键词；
  - 「不成立时」留空是否真的等于这条规则不出现；
  - `添加` 节点追加的正文是否真的进了提示词、并且计入预算后不会把别的规则挤掉；
  - 流程编辑器在手机上展开后是否仍然不横向滚动（CSS 是推断）。
- 流程的变量只在「这一条规则这一次执行」里有效，不落盘、不跨规则共享——想跨轮记住东西，现在还没有地方可放。
- "原件已经变了"目前只记在导入日志里，书架上还没有提示；导出仍然是整本覆盖。
- 悬浮球与浮窗**没有在真实手机上试过**：拖动与点按靠 5px 阈值区分，手指抖动可能误判；
  `resize: both` 的缩放手柄在部分主题下可能看不见。
- 手机整屏用 `100dvh`（回退 `100vh`），老浏览器上地址栏可能遮住底部按钮。
- 手机不再共用电脑那套 DOM（v0.5.0，D-0037）：手机是 `ui/mobile.js` 的整屏 `<dialog>` + `ui/mobile-skin.js` 自带样式，
  电脑仍是 `ui/floating.js` 的悬浮球 + 可拖动浮窗，切换在 `ui/shell.js`。手机这套在 375/500 视口下已用真实浏览器探针验过，
  但 **SillyDroid 这类 WebView 的真机还没试**：`showModal()` 进 top layer 是否与宿主的模态叠加冲突、安卓返回键是否走 `cancel` 事件，
  都只有推断。
- 浮窗"上次是开着"会被记住，刷新后仍开着；不喜欢的话改 `ui/floating.js` 里的 `open` 初值。
- 叙事引擎（v0.6.0 并入，默认关闭）：记账、重放、消息块、注入、设置卡片、自检都已有测试，
  但**真实 SillyTavern 对话端到端还没跑过**——探针只能证明 DOM 与 `setExtensionPrompt` 接线，
  不能证明"模型的下一轮真的会遵守账本"。
- 账本的三个界面（v0.6.1）：设置页「编辑声明」（JSON 校验后才保存）、手机整屏界面顶部的账本坞、
  诊断页的叙事卡片。三者都是只读或"整份替换"级别，**没有**逐条事实的手动补记/撤销入口。
